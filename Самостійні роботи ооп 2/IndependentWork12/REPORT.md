## 1. Опис реалізованих LINQ-пайплайнів

Для моделювання ETL-процесів (Extract, Transform, Load) згенеровано відтворюваний набір даних (`Random(42)`): **60 продуктів**, **70 клієнтів** та **100 записів продажів**.

### Пайплайн 1: «Найпопулярніші продукти за категоріями» (`TopProductsByCategory`)
* **Мета:** Визначити Топ-3 найпопулярніші товари за кількістю проданих одиниць у межах кожної товарної категорії.
* **Використані оператори LINQ та їх призначення:**
  * `GroupBy(s => s.ProductId)` — групує продажі за товаром для підрахунку обсягу продажів кожного продукту.
  * `Select` + `Sum` — агрегує загальну кількість проданих одиниць.
  * `Join` — об'єднує агреговані продажі з таблицею `products` для отримання назви (`Name`) та категорії (`Category`).
  * `GroupBy(x => x.Category)` — формує групи за категоріями.
  * `OrderByDescending` + `Take(3)` — всередині кожної категорії сортує товари за спаданням популярності та відбирає перші 3.

### Пайплайн 2: «Загальний дохід за містами клієнтів» (`TotalRevenueByCity`)
* **Мета:** Оцінити географічний розподіл виручки та кількість замовлень по містах.
* **Використані оператори LINQ та їх призначення:**
  * Подвійний `Join` — зв'язує факт продажу (`Sale`) з ціною товару (`Product.UnitPrice`) та містом клієнта (`Customer.City`).
  * `GroupBy(x => x.City)` — об'єднує транзакції по містах.
  * `Select` + `Sum` + `Count` — обчислює загальний дохід (`Quantity * UnitPrice`) та кількість чеків.
  * `OrderByDescending` — впорядковує міста від найприбутковішого до найменш прибуткового.

### Пайплайн 3: «Продажі за місяцями та роками» (`SalesByYearAndMonth`)
* **Мета:** Побудувати часову динаміку продажів (у штуках та грошовому еквіваленті) помісячно.
* **Використані оператори LINQ та їх призначення:**
  * `Join` — підтягує ціну товару для розрахунку доходу кожної позиції.
  * `GroupBy(x => new { x.Year, x.Month })` — групування за складеним анонімним ключем (рік + місяць).
  * `Select` + `Sum` — підрахунок сумарної кількості товарів та загального виторгу за місяць.
  * `OrderBy` + `ThenBy` — хронологічне сортування спочатку за роком, потім за місяцем.

### Пайплайн 4 (власний): «Топ-5 VIP-клієнтів за 2026 рік» (`TopVipCustomers2026`)
* **Мета:** Виявити найцінніших клієнтів поточного року, які витратили понад 15 000 грн, та перелік категорій, якими вони цікавляться.
* **Використані оператори LINQ та їх призначення:**
  * `Where` (до групування) — раннє відсіювання записів за 2025 рік для зменшення обсягу даних у подальшому `Join`.
  * Подвійний `Join` — отримання даних про клієнта та вартість/категорію товару.
  * `GroupBy` — агрегація покупок за конкретним клієнтом.
  * `Select` + `Distinct` + `string.Join` — формування профілю витрат та унікального списку категорій клієнта.
  * `Where` (аналог SQL `HAVING`) + `OrderByDescending` + `Take(5)` — фільтрація за порогом витрат і вибір п'ятірки лідерів.

## 2. Аналіз продуктивності

| Пайплайн | Орієнтовний час (`ms`) | Примітка щодо виконання |
| :--- | :---: | :--- |
| **1. TopProductsByCategory** | ~1.5 – 4.0 ms | Перший запит у програмі має вищий час через JIT-компіляцію LINQ-виразів та ініціалізацію ітераторів. |
| **2. TotalRevenueByCity** | ~0.3 – 0.8 ms | Виконує два послідовних хеш-з'єднання (`Join` працює за $O(N + M)$). |
| **3. SalesByYearAndMonth** | ~0.2 – 0.6 ms | Швидке групування за числовими полями `Year` та `Month`. |
| **4. TopVipCustomers2026** | ~0.3 – 0.7 ms | Попередня фільтрація `Where` зменшує кількість елементів перед `Join` та `GroupBy`. |

### Які фактори вплинули на час виконання:
1. **JIT-компіляція (перший запуск):** Перший викликаний пайплайн завжди показує більше тіків (`ticks`), оскільки середовище .NET вперше компілює лямбда-вирази та узагальнені методи `Enumerable` у машинний код.
2. **Алокація проміжних об'єктів:** Використання анонімних типів (`new { ... }`) і фінальна матеріалізація через `.ToList()` виділяють пам'ять у купі (Heap).
3. **Внутрішня оптимізація `Join` та `GroupBy`:** У LINQ to Objects оператори `Join` і `GroupBy` будують внутрішні хеш-таблиці (`Lookup<TKey, TElement>`), тому об'єднання даних відбувається за лінійний час $O(N)$, а не за квадратичний $O(N^2)$, як при вкладених циклах.

## 3. Висновки щодо ефективності LINQ для ETL та аналітики

* **Висока читабельність (декларативний стиль):** Складну багатоетапну трансформацію (фільтрація → об'єднання таблиць → групування → сортування) можна описати одним ланцюжком операцій без десятків проміжних словників і вкладених циклів `foreach`.
* **Відкладене виконання (Deferred Execution):** Оператори `Where`, `Select`, `Join` не виконують обчислення до виклику `.ToList()`, що дозволяє комбінувати запити динамічно.
* **Коли варто бути обережним:** На дуже великих обсягах даних (мільйони рядків у реальному часі) часте створення анонімних класів і замикань у LINQ створює додаткове навантаження на збирач сміття (GC), тому в критичних ділянках варто уникати зайвих `.ToList()` всередині ланцюжка та фільтрувати дані (`Where`) якомога раніше.
