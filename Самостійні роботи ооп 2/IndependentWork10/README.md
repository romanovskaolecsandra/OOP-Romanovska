# Самостійна робота №10: Делегати й лямбда-вирази (`CollectionUtils`)

## Опис проєкту
Консольний застосунок на C#, що реалізує статичний узагальнений клас `CollectionUtils` із методами-утилітами (`Map`, `MaxBy`, `Filter`, `ForEach`) на основі стандартних делегатів `Func`, `Predicate` та `Action`.

## Запуск
```bash
dotnet run
```

## Звіт

### 1. Чому делегати корисні для створення таких утиліт?
Делегати дозволяють передавати **поведінку (алгоритм обробки)** як параметр методу. Завдяки цьому один узагальнений метод (наприклад, `Filter` чи `Map`) бере на себе рутинний обхід колекції циклом `foreach`, а конкретне правило фільтрації або перетворення визначається ззовні під час виклику без дублювання коду.

### 2. Як лямбда-вирази спрощують виклик цих методів?
Без лямбда-виразів для кожної простої умови довелося б оголошувати окремий іменований метод у класі. Лямбда-вирази (`p => p.Price > 1500`) дозволяють записати логіку компактно прямо в місці виклику, забезпечують автоматичне виведення типів компілятором і роблять код декларативним та легким для читання.

### 3. Порівняння власних методів із вбудованими LINQ-операторами

| Власний метод | Аналог у LINQ | Основні відмінності |
| :--- | :--- | :--- |
| **`Map`** | `Enumerable.Select` | Наш `Map` виконується **негайно** (одразу створює `List<TResult>` в пам'яті), тоді як `Select` використовує **відкладене виконання (deferred execution)** через `yield return` і обчислює елементи лише при ітерації. |
| **`MaxBy`** | `Enumerable.MaxBy` (з .NET 6+) | Принцип роботи ідентичний (пошук об'єкта за ключем селектора), але вбудований LINQ підтримує передачу власного `IComparer<TKey>` та має оптимізації для різних типів колекцій. |
| **`Filter`** | `Enumerable.Where` | `Filter` приймає делегат `Predicate<T>` і одразу формує новий список; `Where` приймає `Func<T, bool>`, працює як метод розширення (extension method) і підтримує ліниві ланцюжки запитів. |
| **`ForEach`** | `List<T>.ForEach` (у чистому LINQ аналога немає) | LINQ створений для запитів без побічних ефектів, тому в `System.Linq` немає методу `ForEach` (є лише у класу `List<T>`). Наш `CollectionUtils.ForEach` працює з будь-яким `IEnumerable<T>`. |
